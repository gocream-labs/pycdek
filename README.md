# PyCDEK 2

Python library for CDEK API v2.0

API - [ru][api_url_ru] [en][api_url_en]



## Roadmap

Библиотека давно не обновлялась, поэтому актуализация разбита на этапы и два
мажорных релиза.

**2.0.0 - этапы 0-4.** Публичное API остаётся ровно таким же, как в текущей бете
`2.0.0b9`: сигнатуры методов, имена аргументов, типы возвращаемых значений и
текущие (в том числе ошибочные) реакции на ошибки не меняются. Код, работающий с
`2.0.0b9`, продолжит работать без единой правки. Смысл релиза - снять
четырёхлетнюю бету и привести в порядок сборку, тесты, линтеры и документацию,
ничего не ломая пользователям.

**3.0.0 - этап 5.** Всё ломающее: исправление ошибок в самом API, недостающие
эндпоинты, переименования параметров. Отдельный мажорный релиз, потому что
обновиться на него без правок в своём коде уже не получится.

Порядок не случайный: сначала появляется то, чем можно проверять изменения, потом
фиксируется текущее поведение, и только после этого что-то правится.


### 0. Инфраструктура

Модуль `pycdek/` не трогаем вообще - только обвязка вокруг, иначе нечем
контролировать последующие этапы.

* [ ] Починить `.gitignore` - правило `.*` игнорирует все дотфайлы, из-за него
	невозможно закоммитить `.github/`, `.pre-commit-config.yaml` и остальные конфиги.
	Это блокирует всё остальное, поэтому идёт первым пунктом
Инструментарий - [hatch][hatch] (менеджер проекта, [PyPA][pypa]) и `hatchling`
(бэкенд сборки).

* [ ] `setup.py` + `setup.cfg` → единый `pyproject.toml` ([PEP 621][pep_621]),
	бэкенд `hatchling`
* [ ] Версия через `[tool.hatch.version] source = "code"` - функция
	`get_version()` и атрибуты `version` / `__VERSION__` остаются единственным
	источником правды и не меняются. Регексп-ридер (`path = ...`) здесь не годится:
	он ищет литерал и вычисляемое значение не разберёт
* [ ] Dev-зависимости в `[dependency-groups]` ([PEP 735][pep_735]), а не в
	`optional-dependencies` - тогда они не попадают в метаданные пакета и не видны
	пользователям
* [ ] Лицензия строкой SPDX ([PEP 639][pep_639]) вместо classifier и устаревшего
	`license-file`
* [ ] Актуализировать метаданные пакета: имя без пробела, `requires-python`,
	`readme` с указанием content-type (без него PyPI не отрендерит README),
	корректные classifiers. В том числе `Development Status` - к релизу 2.0.0 из
	`3 - Alpha` в `5 - Production/Stable`
* [ ] Настроить `hatch fmt` - внутри уже `ruff` (линт и формат), отдельная
	установка не нужна. Стартовый набор правил сузить явно: дефолтный слишком
	жёсткий для легаси-кода
* [ ] Настроить `hatch test` (pytest с покрытием из коробки) и матрицу окружений
	3.10-3.13 - отдельные `tox` / `nox` не нужны
* [ ] Запрет сетевых вызовов из тестов (`pytest-socket`)
* [ ] `pre-commit`, чтобы локальные проверки и CI не расходились. Локально можно
	гонять через `prek` - тот же формат конфига, заметно быстрее
* [ ] Хук на `commit-msg`, валидирующий формат gitmoji + скоуп: CHANGELOG теперь
	собирается из сообщений коммитов, и кривой коммит молча выпадет из релизных
	заметок

Удалить `setup.cfg` целиком: секция `[isort]` нерабочая (опция `not_skip` удалена
в isort 5), `[wheel] universal = 1` относится к py2/py3-совместимым колёсам,
`[bdist_rpm]` ссылается на несуществующий файл `INSTALL`.

> Форматирование всего репозитория - отдельным коммитом, ничего больше в нём не
> меняя, с добавлением SHA в `.git-blame-ignore-revs`. Иначе `git blame` по
> проекту перестанет быть пригодным.


### 1. Тесты текущего поведения

Задача этапа - не «сделать хорошо», а **зафиксировать как есть**. Без этого на
следующих этапах невозможно отличить «сломал» от «оно и так не работало».

* [ ] Моки HTTP (`responses`) для всех реализованных методов
* [ ] Собрать фикстуры реальных ответов с тестового контура `api.edu.cdek.ru` -
	это единственное, что нельзя восстановить по коду постфактум
* [ ] Golden-тесты на сборку URL и на очистку payload (`clear_dict`)
* [ ] Тесты на известные баги из этапа 5 - с явным комментарием, что поведение
	зафиксировано намеренно


### 2. Модернизация до Python 3.10+

Изменения синтаксические, рантайм не затрагивают.

* [ ] `Optional[X]` → `X | None`, `List`/`Dict`/`Tuple` → `list`/`dict`/`tuple`,
	выпилить лишние импорты из `typing`
* [ ] Убрать `# -*- coding: utf-8 -*-` - в Python 3 это дефолт
* [ ] Проставить аннотации там, где их нет - **строго по факту**, а не по тому, как
	должно быть; иначе это скрытое изменение контракта
* [ ] `@typing.overload` по флагу `origin_response` - методы возвращают `dict` либо
	`Response` в зависимости от него, и это единственный способ описать такое честно,
	не трогая рантайм
* [ ] `py.typed` - **последним пунктом этапа**: после его появления аннотации
	становятся публичным контрактом, и любая неточность превращается в баг у
	пользователей

Нижняя граница 3.10 означает, что `enum.StrEnum` (появился в 3.11) недоступен.


### 3. Актуализация справочников и ссылок

* [ ] Сверить с актуальной документацией тарифы, услуги, статусы, валюты, формы
	собственности
* [ ] Устранить расхождение статусов: одни и те же статусы объявлены дважды с
	**разными значениями** в `client.py` и `statuses.py` (см. таблицу ниже)
* [ ] Заменить ссылки на `confluence.cdek.ru` - домен устарел, документация
	переехала на `api-docs.cdek.ru`
* [ ] Поправить сноски в докстринге `registrate_order`: четыре разные сноски ведут
	на один и тот же URL, три из них неверны
* [ ] Автоматический линк-чекер в CI, чтобы это не протухло снова
* [ ] Таблица покрытия «эндпоинт API v2 → реализован / нет» - без неё непонятен
	объём работ этапа 5


### 4. Безопасные исправления

Только то, что не меняет наблюдаемого поведения.

* [ ] `send()` - внятная ошибка вместо `UnboundLocalError` при неподдерживаемом
	HTTP-методе
* [ ] Сборка URL через `urljoin` вместо `pathlib.Path` - сейчас на Windows
	получается `api.cdek.ru\v2\orders`
* [ ] Привести докстринги `remove_order` / `remove_intakes` к реальности: они
	обещают `dict`, а возвращают `Response`
* [ ] Задействовать `logger` - он создан, но не используется ни разу
* [ ] Убрать мёртвый код и неиспользуемые импорты

Отдельно - правки, меняющие то, что уходит на провод. Требуют проверки на
`api.edu.cdek.ru`, моками не верифицируются:

* [ ] Передавать `client_id` / `client_secret` в теле запроса, а не в query string -
	сейчас секреты попадают в логи прокси
* [ ] `get_deliverypoints` отправляет параметры с именами из API v1
	(`postal_code1`, `city_code1`); Python-сигнатуру при этом не трогаем


### 5. Рефактор и полное обновление - релиз 3.0.0

Единственный этап с ломающими изменениями, поэтому мажорная версия: обновиться с
2.0.0 без правок в своём коде уже не выйдет.

* [ ] Исправить разбор ошибки авторизации - сейчас ветка `CdekApiAccessException`
	фактически мертва
* [ ] Определить семантику пары `raise_errors` / `origin_response`. Сейчас
	`get_order` объявляет `raise_errors`, но не пробрасывает его; при этом «наивное»
	исправление даёт `KeyError` вместо `HTTPError` - нужно решение, а не заплатка
* [ ] Задействовать `CdekRequestException` - объявлен, но не используется, из-за
	чего заявленная возможность ловить ошибки СДЭК отдельно не работает
* [ ] `clear_dict` - рекурсия в списки; сейчас `None`-поля внутри `packages[]`,
	`items[]`, `phones[]` уходят в API как есть
* [ ] Единый источник констант вместо дублирования между модулями
* [ ] `requests.Session` с пулом соединений и ретраями на 429/5xx, настраиваемый
	таймаут вместо захардкоженного
* [ ] Решить судьбу `get_shipping_cost` - метод обращается к калькулятору v1.5
	(`calculate_price_by_json.php`) с MD5-подписью, который СДЭК больше не
	поддерживает
* [ ] Переименовать параметры с опечатками и именами из v1 (`tipe`, `postal_code1`,
	`city_code1`)
* [ ] Добавить недостающие эндпоинты API v2: `PATCH /v2/orders`,
	`/v2/calculator/tarifflist`, `/v2/orders/{uuid}/refusal`, `/v2/prealert`,
	`/v2/registries`, `/v2/check`, `/v2/passport`,
	`/v2/location/suggest/cities`, `/v2/location/postalcodes`, `/v2/payment`
* [ ] Определиться с описанием структур данных (`TypedDict` / `dataclass` /
	`pydantic`) - сейчас это голые `dict` со стострочными докстрингами на метод

* [ ] Проверить, что имя пакета свободно на PyPI - менять его после публикации

* [ ] `CHANGELOG.md` - на него уже ссылаются `MANIFEST.in` и `setup.py`, но файла

* [ ] Определиться с лицензией; смена требует согласия всех контрибьюторов
* [ ] Тестовое приложение на Flask для ручной проверки

Коммиты - в формате gitmoji со скоупом, как в остальных проектах
(`✨ (client): Add ...`). CHANGELOG генерируется
[gitmoji-changelog][gitmoji_changelog] с Python-пресетом:

```sh
gitmoji-changelog --preset python --version-command "hatch version"
```

`hatch version` берётся вместо `python -c "import pycdek; ..."` намеренно: он
работает на чистом чекауте, без установки пакета.

За историю до 2.0.0 CHANGELOG придётся написать руками - существующие коммиты
формату не соответствуют, автогенерация начнёт работать только с новых.

## Release & Versioning

Версии обновляем в соответствии с [мануалом][semver] в это же время репо ведём в соответствии с [gitflow][git_flow].

Общий алгоритм дейтсвий следующий:

0. Write your brilliant code;

1. Start `git flow release start X.X.X[-x.X]`;

2. Обновляем версию в *\_\_init\_\_.py* до соответствующей версии;

3. Коммитим все изменения;

4. Релизим `git flow release finish X.X.X`.

> Незабываем использовать *rc* (release candidate) версии для тестирования обновлений, перед релизом новой стабильной версии.
