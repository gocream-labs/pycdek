    Roadmap¶

    Цель актуализации — сначала сделать проверяемой текущую реализацию, затем выпустить совместимую 2.0.0 и только после этого подготовить 3.0.0 с ломающими изменениями.

    0. Infrastructure¶

    Модуль gocream_pycdek/ на этом этапе не меняем.

    • Исправить исключения в .gitignore для конфигурационных dot-файлов.
    • Перейти с setup.py/setup.cfg/MANIFEST.in на pyproject.toml и Hatchling.
    • Перенести dev-зависимости в [dependency-groups].
    • Объявить лицензию через SPDX и обновить метаданные пакета.
    • Настроить окружения lint/test/mtest с фиксированными версиями инструментов.
    • Настроить статический анализ, матрицу Python 3.10–3.14 и запрет сетевых вызовов в тестах.
    • Добавить pre-commit и commit-msg-хук.

    1. Current Behavior Tests¶

    • Добавить базовые контрактные тесты для всех групп публичных методов клиента.
    • Покрыть HTTP-слой и авторизацию моками responses.
    • Добавить endpoint-level HTTP-моки (responses) для всех реализованных методов.
    • Собрать фикстуры ответов тестового контура api.edu.cdek.ru.
    • Добавить golden-тесты для URL и clear_dict.
    • Зафиксировать баг обработки invalid_client отдельным регрессионным тестом; после исправления тест проходит.
    • Зафиксировать остальные известные баги отдельными тестами.

    2. Python 3.10+¶

    • Перейти на современный синтаксис типов и убрать устаревшие конструкции.
    • Завершить аннотации строго по фактическому поведению.
    • Добавить py.typed последним пунктом этапа.

    3. Documentation, Reference Data and Links¶

    • Настроить сайт документации на Material for MkDocs.
    • Подключить mkdocstrings-python и явно выбрать docstring_style: google.
    • Привести публичные docstring к Google-style и Markdown-разметке.
    • Сверить тарифы, услуги, статусы, валюты и формы собственности с API: недостающие значения добавлены, константы, которых нет в спецификации, помечены комментарием и сохранены до унификации констант в 3.0.0.
    • Устранить дублирование и расхождения статусов: конфликтующие константы из client.py удалены, справочник остался только в statuses.py.
    • Заменить устаревшие ссылки на актуальную документацию API.
    • Добавить линк-чекер.
    • Добавить таблицу покрытия эндпоинтов API v2.

    4. Safe Fixes and 2.0.0¶

    • Пометить get_shipping_cost устаревшим с DeprecationWarning и указанием замены.
    • Перевести URL предметных методов на строки вместо Path.
    • Исправить get_deliverypoints: параметры postal_code, city_code и type в сигнатуре и запросе.
    • Исправить download: возвращать BytesIO, готовый к чтению с начала.
    • Исправить распознавание invalid_client в authorization.
    • Перевести актуальные методы API v2 с clear_dict на drop_none, сохранив явно переданные значения и вложенные структуры.
    • Задействовать логирование и CdekRequestException, сохраняя исходный HTTP-ответ в исключении.
    • Добавить общую Session, освобождение ресурсов через close() и контекстный менеджер.
    • Добавить таймаут по умолчанию и его переопределение через HTTP-настройки.
    • Завершить локальную проверку URL, HTTP-методов, докстрингов и неиспользуемого кода; актуализировать Known Issues. Неподтверждённые изменения сетевого контракта и ограничения совместимости перечислены отдельно.
    • Проверить отдельно изменения, затрагивающие сетевой протокол: проверено на тестовом контуре, результаты в Known Issues.
    • Перед выпуском 2.0.0 перевести Development Status в Production/Stable.

    5. Refactoring and 3.0.0¶

    • Удалить origin_response и raise_errors из предметных методов клиента: возвращать данные, при ошибках поднимать исключения, включая ошибки СДЭК внутри успешного HTTP-ответа. Получение сырого Response и ручную обработку HTTP-ошибок через raise_errors=False оставить в send(); ответ при HTTP-ошибке сохранять в CdekRequestException.response.
    • Удалить устаревшие clear_dict и is_empty: рекурсивная очистка не исправлялась, актуальные методы используют drop_none; clear_dict остался в get_shipping_cost.
    • Унифицировать константы.
    • Добавить ретраи. Общая сессия и настраиваемый таймаут уже реализованы в 2.0.0.
    • Удалить get_shipping_cost в 3.0.0; переходить на calculator_tariff с адаптацией параметров.
    • Удалить region_code и kladr_region_code из get_regions, kladr_region_code из get_cities в 3.0.0: отсутствуют в текущей спецификации API v2, помечены DeprecationWarning в 2.0.0.
    • Переименовать postal_code1, city_code1 и tipe в get_deliverypoints (выполнено в 2.0.0).
    • Переименовать параметры type, затеняющие встроенный type: subscribe.type → event_type (по аналогии с константами WEBHOOK_EVENT_TYPE_*), get_deliverypoints.type → office_type. Соответствует уже принятому для print → request_print принципу - не занимать имена builtin'ов под аргументы.
    • Проверить остальные ошибочные имена параметров.
    • Определить типы структур данных и судьбу имени модуля gocream_pycdek.

    6. Missing Endpoints¶

    Добавление методов не ломает совместимость, поэтому их можно выпускать минорными версиями 3.x. Текущее покрытие - на странице Покрытие API.

    • Локации: подбор города по названию, почтовые индексы города, локация по координатам.
    • Офисы: список офисов внутри прямоугольника координат.
    • Калькулятор: расчёт по доступным тарифам, расчёт с дополнительными услугами, список доступных тарифов.
    • Заказы: изменение заказа, регистрация отказа, клиентский возврат, заявки по заказу.
    • Заявки на вызов курьера: изменение статуса заявки, доступные даты вызова.
    • Договорённости о доставке: интервалы доставки (до и после создания заказа), регистрация и получение договорённости.
    • Преалерты: регистрация и получение информации.
    • Фото документов: заказы с готовыми фото, скачивание архива.
    • Реверс: проверка доступности.
    • Международные заказы: получение ограничений.
    • Реестры наложенного платежа, паспортные данные, чеки.
